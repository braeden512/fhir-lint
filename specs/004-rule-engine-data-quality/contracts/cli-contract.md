**Feature Branch**: `004-rule-engine-data-quality` | **Date**: 2026-09-27  
**Specification**: [`specs/004-rule-engine-data-quality/spec.md`](../spec.md)

---

## 1. CLI Commands & Arguments

The CLI command remains standard POSIX compliant via Picocli:

```bash
fhir-lint validate <file|directory|-> [options]
```

### Options:
- `-p, --profile <NAME>`: Target validation profile (`BASE_R4`, `US_CORE`). Default: `US_CORE`.
- `-f, --format <FORMAT>`: Output format: `table` (default ANSI color table), `json`, `sarif`.
- `--min-score <0-100>`: Minimum passing score. Exits with code `1` if the overall score is below this threshold.
- `--fail-on <SEVERITY>`: Exit with code `1` if any issue of this severity or higher is detected (`error`, `warning`). Default: `error`.
- `-v, --verbose`: Display detailed issue listings in terminal table output.
- `-o, --output <PATH>`: Write output to a file instead of stdout.

## 2. Category Output Integration

Quality issues generated by the Phase 4 rule catalog map directly to existing categories in the score breakdown:
- `CONSISTENCY`: Weight $0.15$
- `TERMINOLOGY`: Weight $0.10$
- `COMPLETENESS`: Weight $0.10$
- `DUPLICATE`: Weight $0.00$ (tracked as diagnostic finding, defect penalties accounted for)

## 3. Exit Code Contract

- `0`: Quality check passed (score $\ge$ `--min-score` and no issues violating `--fail-on`).
- `1`: Quality check failed quality gate thresholds (e.g. any `ERROR` issue when `--fail-on error` is set, or score falls below `--min-score`).
- `2`: Syntax or invocation error (malformed JSON, file not found, invalid flags).
